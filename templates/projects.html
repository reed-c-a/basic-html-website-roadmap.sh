U-Fund Donation Website

In the Spring of 2026, my fourth semester in college, I was part of a software engineering course that introduced me to several web development technologies. The material taught in class was put to practice in a semester-long project in groups of four. My responsibilities and contributions included:

  • Architecting the domain model, and later the UML diagrams, for our program
  • Constructing a working API for all tiers of the back-end with Java Spring Boot throughout the project
  • Testing code both manually via acceptance testing and automatically via unit testing
  • Maintaining a comprehensive design document
  • Facilitating the vast majority of team communications, including Slack messages and in-person meetings
  • Communicating the status of the team's progress to the professor

The project did not go as well as I would have liked, however. The team was composed of four people, but throughout most of the project, the only people doing work were me (doing all of the above) and Connor (doing almost the entire front end, as well as part of the design document). To prevent similar bad experiences, I would be more direct in my communications with team members who need to be more engaged, rather than shy away for fear of seeming like a bother.



Arithmetic Interpreter in C (not publicly available due to course policy)

In the Fall of 2026, I took a course titled "The Mechanics of Programming", which was primarily an introductory C course, but also touched on other topics like operating systems, cryptography, and compilers/interpreters. The final project for the course was an interpreter, the creation of which involved the following:

  • Re-implementing the classic Stack data structure in C with no memory leaks
  • Handling input and output from the user, checking for correctness in formatting
  • Understanding the stages of interpretation, including tokenization, parsing, evaluation, and I/O
  • Ensuring that the program works as intended using the GDB, Valgrind, and manually created test programs for each module and the finished product
  • Maintaining a record of the project with version control via GitHub

This was a solo project that I spent just over a month on, and it was a resounding success. I worked consistently and in a focused manner, reading the provided write-up carefully and testing thoroughly before making assumptions about the progress of the project. By this point in my college tenure, I had come to realize that the sooner I got started on a piece of assigned work, the more enjoyment I found in it and the less detrimental pressure I experienced. I feel as though this project was the product of a lot of difficult lessons learned and applied.
